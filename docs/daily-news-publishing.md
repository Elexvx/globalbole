# 日更新闻发布流程

## 固定目标

- GitHub：`Elexvx/globalbole`，发布分支 `main`
- 简体中文稿件：`content/issues/YYYY-MM-DD/zh-CN/`
- 正式站点：<https://www.globalbole.com/zh-CN/>
- 现有部署方式及项目见 [生产部署说明](production-deployment.md)

## 编辑要求

1. 从当天简报选择科技与AI、财经商业、就业城市生活、国内外要闻、能源产业及创新相关的独立新闻，不为凑篇数发布未核实内容。
2. 打开原始链接核对事件日期、发布日、数字、限定条件与更新。动态数据页面应同时保留发布日及本次使用的数据期，后续可换为官方归档链接。
3. 独立撰写有实质信息的完整文章：保留原报道关键事实、数据、条件与必要背景，再给出有依据的分析，使用自然表述区分事实与推论。不得只生成几句摘要；篇幅由信息量决定，不为凑字数重复。引用仅限必要短句，不成段搬运原文。清晰区分事实、报道转述与编辑分析。不移入私人简报中的个人情况、个人建议或内部引用标记。不添加“本站整理日期”“判断口径”“伯乐判断”等流程化标注或尾注；保留实质分析、必要事实限定、可核查来源和图片署名许可。
4. 全文以编辑视角撰写，稍正式、专业但自然，允许适度口语感，避免公文腔或机械套话。来源采用文末编号附注：每条给出原始发布日期、原文标题及链接；正文用上标关联，保留必要事实归属，不穿插书目式说明。文章 `date` 是本站刊发日，不能把旧事件写成当天发生。
5. 配图只使用本篇所引原始报道、公告或研究材料里已有的照片、图表，并先核实允许转载的明确许可或公有领域依据。尽量采用多张内容相关、信息互补的原图，不重复同一张凑数，不用无关图库资料照替代。新闻配图与所有数据图都不得自行绘制、重新制图或使用生成式图片工具。来源只有数据但没有可复用图像时，保留重要数字的文字表述。没有合适且获准使用的原图时，将 `cover` 与 `coverAlt` 同时设为 `""`，使用完整的纯文字版式，不生成占位图或保留空图片框。全站封面直接复用该文章正文已有的获准原图，不另行生成封面。所有封面均等比放大铺满版式框，不拉伸、不留空边，并保留主体；正文数据图必须完整显示，不能裁掉坐标、数值或注释。正文配图来源应可核实。图注只列已核实的时间、地点、人物、摄影者、授权方及授权原则，保留必要版权署名和许可链接；资料照片标明真实时间。缺少的字段直接省略，不填未知或自行推测，不加入处理流程说明。图片存放于 `public/news-media/YYYY-MM-DD/`，保存机器可读许可记录。不要把来源署名视为转载许可。 发布前检查新图片的 EXIF、IPTC、XMP 等元数据；以保持图像像素及必要色彩配置的方式去除非必要的个人联系方式、定位等信息，重新记录文件哈希。许可要求的作者、版权及授权信息继续保留在可见图注和许可记录中。
6. 署名为“全球伯乐 News”，身份“资料整理”，不暗示现场采访。先发简体中文；其他语言仅在提供完整译文后新增。

## 去重和重试

`docs/news-publication-log.json` 记录批次、稳定 `translationKey`、原始来源及日期，只记录公开新闻事实，不保存账户凭据或私人简报内容。

- 开始前同时检查 `main` 最新稿件、日志和正式站点的 `/data/v1/articles.json`。
- 以来源 URL + 事件/数据期 + 主题识别同一新闻。不要仅依靠可变的页面 URL（例如最新月报主页）或当日日期去重。
- 同一稿件复跑时复用路径、slug 和 translationKey。内容与来源未变则跳过提交。
- 已提交但未部署：验证原提交后继续部署该版本，不再生成重复文章。
- 只有存在实质更新时修改旧稿或新写后续稿，正文说明更新日期及变化。
- 批次日期不代表部署已成功。GitHub 提交、部署 READY、正式域名可读分别验证。

## 验证和提交

```sh
npm ci
npm test
NEXT_PUBLIC_SITE_URL=https://www.globalbole.com npm run build
npm run lint
npm run check:export
```

检查首页、每篇正文、来源链接、本地封面、分类页、RSS 和 sitemap；至少查看一篇渲染后的页面。不得跳过失败检查后直接发布。

拉取或读取 `main` 最新 SHA 后创建只包含本批内容与必要校验维护的提交，保留所有原有文件。不强制推送。若在验证期间 `main` 已前进，先合入最新内容并重新验证。

没有 CLI GitHub 凭据时，可用已授权的 GitHub 连接读取仓库，并用 Git Trees/Commits/Refs 接口原子提交：新 tree 以当前 main 的 tree 为基础，commit 以当前 main 为父提交，ref 更新禁止 force。

## 部署成功的定义

本项目已连接公开 GitHub 仓库的原生自动部署，生产分支为 main。向 main 提交会触发既有 Vercel 项目构建；仍不能把 push 成功当作上线成功。使用原有项目与域名，不新建项目、令牌、权限或付费方案，也不默认回退到文件夹投放。

部署后确认 Vercel 的 Git commit SHA 与本次提交完全一致，构建状态为 READY，且正式域名指向该部署。旧的浏览器投放发布没有 Git SHA，不应用来证明新提交已上线。再从 `https://www.globalbole.com` 读取文章数据和每篇页面。部署不可用时保留已验证的提交，明确报告“稿件已提交，网站部署待完成”，不得报告已上线。

## 历史发布方式

2026-10-03 接通 GitHub 原生部署前曾使用现有项目的浏览器文件夹发布。该方式已停止用于日常发布；不得回退为文件夹投放。当前只遵循上面的原生 Git 部署与同一 SHA 验证流程。

## 图注格式

图注只写已知的时间、地点、人物、摄影者、授权方与许可原则；缺少的字段直接省略。保留许可要求的作品题名、版权署名、来源和许可链接。不加入图片处理流程或版式说明。直接转载的原始数据图注明数据期、数据来源与原制图机构，附原始作品及许可链接；不得把源图改写为本站制图，不编造摄影或授权信息。

所有封面使用等比铺满（object-fit: cover），根据主体检查焦点，避免切掉人脸或关键内容；正文图片保持自然比例完整展示，数据图的坐标、数值及注释须清晰可读。封面复用原图文件，图注不写版式处理说明。若实际修改图片文件或制作改编作品，应先检查具体许可义务。

## 栏目归类

保留 `technology`（科技/AI）、`business`（财经与商业）、`innovation`（创新）的既有URL；新增 `work-life`（就业与城市生活）、`current-affairs`（国内外要闻）、`energy`（能源与产业）。按文章主要问题选择一个主栏目，交叉主题使用标签，不为填满栏目重复发布。新增栏目由统一导航与分类页承载，空栏目不借用其他栏目文章。
